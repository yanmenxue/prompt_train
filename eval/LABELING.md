# Intent Router 数据标注规范 v1

本规范只依据两个真实下游 Agent 的能力，不依据词面相似度，也不为了提高模型分数
改变标签。每条样例的最终标签只能是 `SearchStockQuotes`、`RecommendProduct` 或
`null`。

## 标注步骤

1. 读取完整对话，恢复省略、指代、否定和目标变更后的当前最终目标。
2. 区分用户要求完成的核心动作与仅作为背景、约束、例子或被否定的词语。
3. 分别识别请求中可由股票或商品 Agent 处理的子任务；主 Agent 可以继续处理未分发的
   其它子任务。
4. 按以下能力边界标注最终系统输出，再标注仅供诊断的虚拟候选。
5. 设置、写作、票务、证券操作、旧订单等附带任务不遮蔽唯一的股票信息或商品发现
   子任务；股票和商品两种能力同时出现、要求分别发现/购买多个互不相关商品，或另有
   股票预测/荐股、整车/房产重大推荐等不能忽略的独立目标时，标为 `null`。

## `SearchStockQuotes`

原始能力：获取股票市场、股票名称、股票代码的价格、走势、行情、K 线等动态实时
股票信息；用户直接指定股票类软件查询信息；根据问题回答股市相关问题。不支持股票
预测和推荐。

应返回：

- A 股、港股、美股等具体股票的当前或历史价格、涨跌、成交量、K 线和行情。
- 上证、深证、创业板、恒生、标普 500、纳斯达克等股票市场指数行情。
- 股票财务指标、公告、分红、估值指标以及明确的股票市场事实或概念问答。
- 股息率等股票市场指标的一般解释、历史经验和阈值讨论；这里的“怎么选择合适范围”
  不等同于替用户选择具体股票。
- ETF 或指数基金所代表股票市场的点位、位置和振幅；即使同一段前文评论过收益，只要
  当前最终问题明确转向市场点位，就不是查询基金自身收益。
- 对已经发生的涨跌、行情或市场事件询问原因；不包含未来预测或买卖建议。
- 明确要求在同花顺、雪球、国泰君安、中信证券、国信证券、投资堂等股票类软件中
  查询上述信息。

不应返回：

- 未来涨跌、目标价、收益预测、荐股、选股、买卖时机、仓位和投资建议。
- 假设未来市场下跌后判断哪些板块先跌，以及判断股价是否已经反映未来业绩等条件
  预测或估值结论。
- 只给出上市公司名称或只陈述一段资金、板块观点，且没有查询、分析或操作请求。
- 证券开户、登录、银证转账、委托下单、撤单、账户或软件操作。
- 炒股软件的推荐、比较、下载或使用教程。
- 基金、债券、期货、外汇、黄金、加密货币、银行理财等非股票对象的查询或建议。
- ETF/基金自身的标的选择、净值或交易价格；借 ETF 询问其代表的股票指数或板块点位
  时才按股票市场信息处理。

模型侧诊断候选：事实查询标为 `stock_market_information`；预测与建议标为
`no_route_stock_advice`；公司龙头、赛道、持股与业绩/股价关系等深度研究标为
`no_route_stock_research`；其它股票相关目标标为 `no_route_stock_other`。

## `RecommendProduct`

原始能力：根据用户需求在京东、淘宝等电商平台检索并推荐合适商品，涵盖品类选购
建议和高性价比单品推荐。选中后会打开电商平台助手。

应返回：

- 普通电商商品的推荐、搜索、筛选、选型、比价、购买链接和购物清单。
- “想买”“给我买一个”等尚未指向已展示商品或已有订单的口语化商品发现需求。
- 指定京东、淘宝、天猫、拼多多等电商平台查询某件普通商品。
- 明确查看或搜索一个具体成品、替换电池等可购买配件，以及“搜同款”这类约定俗成的
  商品发现动作。
- “推荐充电”“看看电源”等 ASR 截断表达在动作明确且剩余词仍可识别为常见零售品时，
  按商品发现处理；不能把任意未知词套入该规则。
- 为购买决策比较多个具体商品，或询问某一品类怎么选、哪款适合。
- 未给出具体型号、根据房间面积或人数等使用场景反推某品类应选的规格或性能参数。
- 书籍、食品、服饰、家电、数码、家具、玩具、汽车配件等可在普通电商平台检索的
  实体商品；“股票入门书”等不会因为主题词而变成股票查询。

不应返回：

- 汽车、房产、保险、金融产品、旅游产品、招聘、家政、维修、医疗或法律服务。
- 摩托车等整车和处方药/非处方药；即使用户指定京东、淘宝购买也不进入普通商品 Agent。
- 已展示/选定商品或已有订单的下单、支付、取消、退款、物流、发票和售后操作。
- 已知具体型号的参数、适用性，以及商品使用方法、故障排查、维修、真伪鉴定或纯
  知识问答，且当前没有购物目标。
- 商品型号介绍、品牌销量与平均售价等市场统计，且没有搜索、展示或购买动作。
- App、炒股软件、游戏账号、会员代充等非普通实体电商商品。

模型侧诊断候选：符合普通电商发现需求标为
`ecommerce_product_recommendation`；纯参数、价格、适用性和已有设备兼容问答标为
`no_route_product_information`；已有商品、订单或交易目标标为
`no_route_product_other`；整车、房产、票务和服务标为 `no_route_non_retail`。

## `null`

除上述两个能力外均不分发，由主 Agent 继续处理。纯闲聊标为
`no_route_chitchat`；完全不属于股票或商品大类、指代不足、多独立目标标为
`no_route_no_available`。所有虚拟候选最终系统输出均为 `null`，因此最终验收以
系统输出为准，虚拟候选 exact match 仅用于分析 prompt 的语义组织。

## 多轮优先级

- 当前消息承接前文：“那它呢”“第二个呢”需恢复指代。
- 用户明确改口、纠正或取消旧目标时，以最新目标为准。
- 助手提到某个候选不等于用户选择该候选。
- 问候、礼貌语、预算、用途等从属内容不构成独立目标。
- “查股价并推荐耳机”同时需要两个 Agent，标为 `null`；“查股价并写邮件”标为
  `SearchStockQuotes`，邮件由主 Agent 继续处理；“推荐一本讲 K 线的书”只有商品
  购买目标，标为 `RecommendProduct`。
- “推荐商品并预测股票”“查股票并推荐整车”“推荐商品并推荐房产”还包含另一个重大
  独立目标，标为 `null`；证券撤单、旧订单查询等操作性附带任务不采用这一规则。

## 数据审校要求

- `id`、完整消息序列不得重复。
- 最后一条消息必须来自用户；不包含主 Agent 的 system message。
- 每条必须有明确、唯一的当前主要目标；专门测试信息不足的样例除外。
- `expected_system_output` 必须和本规范一致；`expected_candidate_id` 不得与它冲突。
- 数据生成后逐条检查文本、上下文、标签和诊断候选，并运行结构、重复、分布及
  关键词冲突检查。数据文件冻结后以 SHA-256 标识实验版本。
